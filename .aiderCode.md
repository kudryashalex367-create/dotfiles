# ТЗ: агент для дотфайлов (Arch Linux, bare-git)

## 0. Контекст
- Рабочая директория — $HOME. Репозиторий bare-git, публичный, ветка только `main`, remote `origin`.
- Git ТОЛЬКО через `config`, `cpush`, `cpull`. Сырой `git ...` не использовать: вывод через `config` читаемее. Прямой путь `/usr/bin/git --git-dir=$HOME/.cfg/ --work-tree=$HOME` не использовать никогда, ни при каких обстоятельствах. Если алиаса/функции нет в твоём шелле, один раз скажи об этом и остановись, не придумывай обходов.
- `cpush` запускать только после моего «да» на предложенное название (раздел 5.2). Сырой `git push` не использовать никогда.
- `status.showUntrackedFiles = no`: новые файлы не видны в `config status`, пока их явно не добавили.
- Aider запущен с `--no-git --yes`: автокоммитов и подтверждений нет. Страховка — git (для чистых tracked-файлов), бэкап (для остальных) и твоя аккуратность.
- Hyprland применяет конфиг сразу при сохранении, поэтому после каждой правки сразу проверка.
- Общение: по-русски, коротко, без воды.

## 1. Принципы
1. Задача чёткая → делай её и только её. Лишнее, что заметил рядом, не чини, а одной строкой в конце («Заметил: ...»).
2. Задача свободная («на своё усмотрение», «сделай красиво/круто», «почини», «разберись») → инициатива в рамках названного файла или секции, любого объёма. Не удаляй рабочие вещи без причины.
3. Любая правка обратима. Сомневаешься, спроси одним коротким вопросом, без догадок.
4. Экономь шаги и токены (раздел 6). Не делай ничего «на всякий случай».

## 2. Что можно, а что нельзя

**Можно без вопросов**
- Читать любые файлы в $HOME (кроме секретов, см. ниже), править их, создавать новые под задачу.
- Править несколько файлов, если задача этого требует. Если файлов больше 10, сначала план в 2 строки и «ок?».
- Запускать проверки (раздел 4), `makoctl reload`, `hyprctl configerrors`, `niri validate`.
- Читающий git: `config status/diff/log/show/ls-files/branch`.
- Коммит и пуш только через `cpush` по сценарию раздела 5 (после моего «да»).

**Только по прямой просьбе в текущем сообщении**
- `config add -- <новый файл>` (взять новый файл под контроль)
- `config commit --amend`, и только для ещё не запушенного коммита
- Удалить, переименовать, переместить файл (кроме своих бэкапов и файла, созданного тобой в этой сессии)
- Править списки пакетов (`.config/pkglist_*.txt`), конфиги WM и сессий, не упомянутых в задаче. Не трогай их, если не просили.

**Нельзя никогда без явной команды**
- Git: `git push` напрямую (никогда, даже по команде: пуш только через `cpush` или `config push origin main`), `add -A`, `add .`, `add -f`, `push --force/-f/--force-with-lease/--tags`, push не в `main`, `reset`, `clean`, `checkout -f`, `checkout .`, `restore .`, `stash`, `rebase`, `rm`, `gc`, `prune`, `filter-branch`, `remote ...`, `config config ...` (включая `status.showUntrackedFiles`).
- Система: `sudo`, `pacman`/`yay` (установка и удаление), `systemctl`, `chsh`, `rm -rf`, `kill`/`pkill`, выход из сессии, перезапуск композитора и сервисов, запуск `hyprlock`, правка файлов вне $HOME.
- Секреты: `~/.zshrc_secrets`, `~/.ssh`, `~/.gnupg`, внутренности `~/.cfg/`, файлы с `secret`, `key`, `token`, `credential`, `password` в имени, `.env`. Не читать, не выводить, не бэкапить, не коммитить. Не печатать переменные окружения (`env`, `printenv`, `echo $...KEY`).

## 3. Работа с файлами
**Preflight (один раз за сессию, перед первой правкой):** `config status -sb | head -20`.
- Файлы, изменённые ещё до тебя, считай «чужими»: не откатывай их, не выдавай за свои.
- Бэкап нужен только для «грязных» (уже изменённых до тебя) и неотслеживаемых файлов: `cp --parents F ~/dotfiles-backup/aider/<YYYY-MM-DD_HHMMSS>/` (каталог один на сессию, файл бэкапится при первом касании). Чистый tracked-файл не бэкапь: его бэкап это git.

**Правка:** только в diff-формате, файл целиком не переписывай. Не трогай отступы, порядок и комментарии вне затронутых строк. Где правка неочевидна, оставь короткий комментарий в стиле файла.

**Откат** (если проверка не прошла или он просто нужен):
- файл был чистым → `config restore -- F`
- файл был «грязным» → `cp <бэкап> F`
- файл создан тобой → удалить его, только если попросили.

**Страж размера:** после правки смотри `config diff --stat` (для неотслеживаемых `wc -l`). Файл резко похудел, а удаление не просили → сразу откат и сообщи.

## 4. Проверка (после каждой правки, до коммита)
| Файл | Проверка |
| :-- | :-- |
| `.config/niri/*` | `niri validate` |
| `.config/hypr/hyprland.*` | `hyprctl configerrors` (пусто = ок), ручной reload не нужен |
| `.zshrc`, `*.zsh` | `zsh -n <файл>` |
| скрипты в `.local/bin` | `bash -n` или `zsh -n` по shebang, `shellcheck` если есть |
| `.config/mako/*` | `makoctl reload` |
| `*.json` | `jq . <файл>` |
| `*.toml` | `python -c 'import sys,tomllib;tomllib.load(open(sys.argv[1],"rb"))' <файл>` |
| остальное (kitty, fuzzel, hyprlock...) | автопроверки нет: скажи об этом и как проверить глазами |

Проверка не прошла → одна попытка починить → снова не прошла → откат и текст ошибки. Больше двух попыток не делай.

## 5. Git-сценарий (главное)

### 5.1 Ритуал: «посмотреть и предложить коммит» — ОДИН вызов
Запускай ритуал автоматически, когда закончил задачу с правками, и по любой просьбе вида «коммит», «пуш», «cpush», «что изменилось». Одна команда, не раздроблённая на пять:

```
config status -sb; echo '--- stat'; config diff HEAD --stat; echo '--- diff'; config diff HEAD -U1 | head -150; echo '--- log'; config log --oneline -8; echo '--- secrets'; config diff HEAD -U0 | grep -E '^\+' | grep -Eiq '(api[_-]?key|secret|token|passw|bearer|sk-[A-Za-z0-9]{10,}|ghp_|BEGIN [A-Z ]*PRIVATE KEY)' && echo '!!! ПОХОЖЕ НА СЕКРЕТ' || echo 'ок'
```

Дальше ответ из 3 частей, больше ничего:
1. Что изменилось: 1–2 строки по существу, без пересказа diff (он уже на экране).
2. Предупреждения, если есть: «чужие» изменённые файлы, новые неотслеживаемые файлы, созданные в этой сессии («добавить X?»), срабатывание на секреты.
3. Строка: `cpush "<название>" — пушим?`

**Название коммита:** по стилю последних коммитов из лога (язык, регистр, формат вроде «область: что»), по-русски, до 72 символов, по сути изменений. Без слов «aider», «checkpoint», без эмодзи. В названии не использовать `"`, `$`, обратные кавычки и `!` (шелл их раскроет).

Сработало «!!! ПОХОЖЕ НА СЕКРЕТ» → не предлагай коммит, покажи подозрительные строки (замаскируй значения) и жди указаний.

### 5.2 Подтверждение
- Перед `cpush`: если после последнего ритуала файлы менялись (тобой или в `config status -s` появилось новое), повтори ритуал и предложи название заново. Пушить то, что я не видел, нельзя.
- «да», «ага», «давай», «+», «ок», «пушь», «cpush» после предложения → `cpush "<название>"` ровно с предложенным названием, без повторных проверок и вопросов.
- Если я дал своё название, используй его.
- «нет», «подожди» → ничего не делай.
- Новый файл в предложении и я согласился → сначала `config add -- <файл>`.
- Есть «чужие» изменённые файлы, а `cpush` берёт все tracked-изменения (`add -u`) → в предложении спроси «всё или только мои?». Если «только мои»: `config add -- F1 F2` → `config commit -m "<название>"` → `config push origin main`.

### 5.3 После cpush
Одна команда: `config status -sb | head -3; config log --oneline -3` и итог одной строкой («запушено: <название>»).
- Отклонён (non-fast-forward) → не форси, скажи и предложи `cpull`.
- Ошибка авторизации → не повторяй, скажи.

### 5.4 cpull
Только по просьбе. Запускай `cpull`.
- Если предварительно `config status -s` показывает локально изменённые файлы, которые затронет pull, сначала спроси.
- Конфликт → ничего не резолви сам, `config merge --abort`, перечисли файлы, жди.
- После pull: список изменившихся файлов, проверки из раздела 4 (только отчёт, ничего не чини), напомни, что нужен перезапуск. Если менялся `.zshrc`, скажи мне выполнить `exec zsh` самому.

## 6. Экономия
- Не запускай команды «на всякий случай» и не повторяй проверки, после которых файл не менялся.
- Нужна секция, а не весь файл: `grep -n`, `sed -n 'A,Bp'`. Длинный вывод режь `| head -50`, `| tail -30`.
- Не трогай и не показывай файлы, которые не правишь.
- Типовая задача (правка → проверка → ритуал) укладывается в ~5–8 команд. Нужно больше ~12, остановись и объясни, почему.
- Отчёт сверх ритуала не пиши: ритуал и есть отчёт. Дополнительно одной строкой: как проверить глазами (если автопроверки нет) и «Заметил, но не трогал: ...» (если есть).

## 7. Когда остановиться и спросить
- Нужен файл вне $HOME, `sudo` или файл из списка секретов.
- Нужно удалить, переименовать или переместить файл.
- Проверка не прошла после двух попыток.
- Push отклонён, ошибка авторизации, конфликт при pull, срабатывание на секреты.
- Нужен push → предложи название и жди моего «да»; запускай только `cpush` (или `config push origin main` в случае «только мои»), `git push` — никогда.
- Нужна команда, которой нет в этом ТЗ.
- Непонятно, что именно просили.
