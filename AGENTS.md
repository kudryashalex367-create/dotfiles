# ТЗ: агент для дотфайлов (Arch Linux, GNU Stow)

## 0. Контекст
- Рабочая директория — `$HOME/dotfiles`. Обычный git-репозиторий, публичный, ветка только `main`, remote `origin`.
- Пакеты Stow: zsh, hypr, mango, kitty, fuzzel, mako, fastfetch, matugen, bin, pkglists, ai, starship. Линкуются в `$HOME` командой `./install.sh` (или `stow --no-folding -d "$HOME/dotfiles" -t "$HOME" -R <пакет>`).
- Править ТОЛЬКО файлы внутри `~/dotfiles`, никогда по путям в `$HOME` (`sed -i` ломает симлинк).
- Новый, удалённый или переименованный файл в пакете появится в системе после рестоу.
- Git использовать напрямую (`git status`, `git diff`, `git log`).
- Коммит и пуш — только после моего «да» (раздел 5).
- Hyprland применяет конфиг при сохранении. Mango — после `reload_config` (SUPER+SHIFT+R).
- Общение: по-русски, коротко, без воды.

## 1. Принципы
1. Задача чёткая → делай её и только её. Лишнее, что заметил рядом, не чини, а одной строкой в конце («Заметил: ...»).
2. Задача свободная («на своё усмотрение», «сделай красиво/круто», «почини», «разберись») → инициатива в рамках названного файла или секции, любого объёма. Не удаляй рабочие вещи без причины.
3. Любая правка обратима. Сомневаешься, спроси одним коротким вопросом, без догадок.
4. Экономь шаги и токены (раздел 6). Не делай ничего «на всякий случай».

## 2. Что можно, а что нельзя

**Можно без вопросов**
- Читать файлы в `~/dotfiles`, править их, создавать новые под задачу.
- Править несколько файлов, если задача требует. Файлов больше 10 → сначала план в 2 строки и «ок?».
- Проверки (раздел 4), `makoctl reload`, `hyprctl configerrors`, рестоу пакета.
- Читающий git: `status/diff/log/show/ls-files/branch`.
- Коммит и пуш только по сценарию раздела 5 (после моего «да»).

**Только по прямой просьбе в текущем сообщении**
- `git add -- <новый файл>` (взять новый файл под контроль)
- `git commit --amend`, и только для ещё не запушенного коммита
- Удалить, переименовать, переместить файл (кроме своих бэкапов и файла, созданного тобой в этой сессии)
- Править списки пакетов (`.config/pkglist_*.txt`), конфиги WM и сессий, не упомянутых в задаче. Не трогай их, если не просили.

**Нельзя никогда без явной команды**
- Git: `push` без ритуала и моего «да», `add -A`, `add .`, `add -f`, `push --force/-f/--force-with-lease/--tags`, push не в `main`, `reset`, `clean`, `checkout -f`, `checkout .`, `restore .`, `stash`, `rebase`, `rm`, `gc`, `prune`, `filter-branch`, `remote ...`.
- Система: `sudo`, `pacman`/`yay`, `systemctl`, `chsh`, `rm -rf`, `kill`/`pkill`, выход из сессии, перезапуск композитора и сервисов, запуск `hyprlock`, правка файлов вне `~/dotfiles`.
- Секреты: `~/.zshrc_secrets`, `~/.ssh`, `~/.gnupg`, `~/.gemini`, `.env`, файлы с `secret`/`key`/`token`/`credential`/`password` в имени. Не читать, не выводить, не бэкапить, не коммитить. Не печатать окружение (`env`, `printenv`, `echo $...KEY`).

## 3. Работа с файлами
**Preflight (раз за сессию, перед первой правкой):** `git status -sb | head -20`.
- Файлы, изменённые до тебя, — «чужие»: не откатывай, не выдавай за свои.
- Сгенерированные matugen файлы (`hypr/.config/hypr/colors.lua`, `hyprlock.conf`, `fuzzel/.config/fuzzel/fuzzel.ini`, `mako/.config/mako/config`) всегда «грязные»: руками не правь (правь шаблоны в `matugen/`), в предупреждения ритуала не включай.
- Бэкап нужен только «грязным» и неотслеживаемым файлам: `cp --parents F ~/dotfiles-backup/agent/<YYYY-MM-DD_HHMMSS>/` (каталог один на сессию, при первом касании файла). Чистый tracked-файл не бэкапь: его бэкап — git.

**Правка:** точечно (diff/edit), файл целиком не переписывай без нужды. Не трогай отступы, порядок и комментарии вне затронутых строк.

**Откат:** чистый файл → `git restore -- F`; «грязный» → `cp <бэкап> F`; созданный тобой → удалить, только если попросили.

**Страж размера:** после правки `git diff --stat` (для неотслеживаемых `wc -l`). Файл резко похудел, а удаление не просили → сразу откат и сообщи.

## 4. Проверка (после каждой правки, до коммита)
| Файл | Проверка |
| :-- | :-- |
| `hypr/**/hyprland.*`, `hypr/**/*.lua` | `hyprctl configerrors` (пусто = ок) |
| `mango/**` | автопроверки нет: после правки `reload_config`, смотреть ошибки в логе композитора |
| `*.zsh`, `.zshrc` | `zsh -n <файл>` |
| `bin/.local/bin/*` | `bash -n` / `zsh -n` по shebang, `shellcheck` если есть |
| `mako/**` | `makoctl reload` |
| `*.json`, `*.jsonc` | `jq . <файл>` |
| `*.toml` | `python -c 'import sys,tomllib;tomllib.load(open(sys.argv[1],"rb"))' <файл>` |
| остальное | автопроверки нет: скажи и как проверить глазами |

Проверка не прошла → одна попытка починить → снова не прошла → откат и текст ошибки. Больше двух попыток не делай.

## 5. Git-сценарий (главное)

### 5.1 Ритуал — ОДИН вызов
Запускай автоматически после задачи с правками и по просьбе «коммит», «пуш», «dpush», «что изменилось»:
```
git status -sb; echo '--- stat'; git diff HEAD --stat; echo '--- diff'; git diff HEAD -U1 | head -150; echo '--- log'; git log --oneline -8; echo '--- secrets'; git diff HEAD -U0 | grep -E '^\+' | grep -Eiq '(api[_-]?key|secret|token|passw|bearer|sk-[A-Za-z0-9]{10,}|ghp_|BEGIN [A-Z ]*PRIVATE KEY)' && echo '!!! ПОХОЖЕ НА СЕКРЕТ' || echo 'ок'
```

Ответ из 3 частей и больше ничего:
1. Что изменилось: 1–2 строки по существу.
2. Предупреждения, если есть: «чужие» файлы, новые неотслеживаемые («добавить X?»), срабатывание на секреты.
3. `Коммит "<название>" — пушим?`

Название: обычная фраза по-русски по сути изменения, без префикса-области и двоеточия (`mango: ...`, `zsh: ...` — нельзя), до 72 символов, без `"`, `$`, обратных кавычек и `!`, без слов «agent/aider/opencode», без эмодзи.

Сработало «!!! ПОХОЖЕ НА СЕКРЕТ» → не предлагай коммит, покажи подозрительные строки (замаскируй значения) и жди указаний.

### 5.2 После «да»
- Новые файлы, согласованные в сессии: `git add -- <файлы>`.
- `git add -u` (или `git add -- F1 F2`, если выбрал «только мои»).
- `git commit -m "<название>" && git push origin main`.
- Затем `git status -sb | head -3; git log --oneline -3` и итог одной строкой.
- Если после ритуала файлы менялись — повтори ритуал. Пушить то, что я не видел, нельзя.

### 5.3 cpull
Только по просьбе. Запускай `cpull`.
- Если `git status -s` показывает локально изменённые файлы, которые затронет pull, сначала спроси.
- Конфликт → ничего не резолви сам, `git merge --abort`, перечисли файлы, жди.
- После pull: список изменившихся файлов, проверки из раздела 4 (только отчёт, ничего не чини), напомни про перезапуск. Если менялся `.zshrc`, скажи мне выполнить `exec zsh` самому.

## 6. Экономия
- Не запускай команды «на всякий случай» и не повторяй проверки, после которых файл не менялся.
- Нужна секция, а не весь файл: `grep -n`, `sed -n 'A,Bp'`. Длинный вывод режь `| head -50`, `| tail -30`.
- Не трогай и не показывай файлы, которые не правишь.
- Типовая задача (правка → проверка → ритуал) укладывается в ~5–8 команд. Нужно больше ~12, остановись и объясни, почему.
- Отчёт сверх ритуала не пиши: ритуал и есть отчёт. Дополнительно одной строкой: как проверить глазами (если автопроверки нет) и «Заметил, но не трогал: ...» (если есть).

## 7. Когда остановиться и спросить
- Нужен файл вне `~/dotfiles`, sudo или секрет.
- Нужно удалить, переименовать или переместить файл.
- Проверка не прошла после двух попыток.
- Push отклонён, ошибка авторизации, конфликт при pull, срабатывание на секреты.
- Нужен push → предложи название и жди моего «да»; запускай только `git push origin main` после коммита.
- Нужна команда, которой нет в этом ТЗ.
- Непонятно, что именно просили.
